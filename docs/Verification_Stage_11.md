# Morimundus — проверка этапа 11

Дата: 9 октября 2026 года. Этап: аккаунты и размещение.

Реализованы вход через ChatGPT, серверные права автора, отдельная опубликованная редакция, страница игры и сохранения каждого аккаунта. Гость получил локальные слоты браузера. Типы, сборка и 299 автоматических проверок проходят. Настоящий вход через платформу, два физических устройства и браузерная приёмка остаются открытыми.

## Реализованное поведение

Sign in with ChatGPT обслуживает сама платформа. Ссылки входа и выхода переходят в верхнее окно через официальный помощник `app/chatgpt-auth.ts`; приложение не реализует пароли и не подменяет служебные маршруты. Идентификатор и почта читаются из подтверждённых платформой заголовков. Без обоих значений аккаунтные API отвечают 401.

Начальная привязка автора сравнивает подтверждённую почту с секретом исполнения `MORIMUNDUS_AUTHOR_EMAIL`. В D1 атомарно закрепляется идентификатор автора; последующие запросы сверяют этот идентификатор. Другой идентификатор с той же почтой не получает права уже привязанного автора. Настоящие личные данные и секрет не входят в исходники. Мастерская, проект, загрузка файлов, публикация и прежние проверочные слоты требуют авторского права на сервере.

Автор сохраняет проект и явно публикует его в разделе «Игра по ссылке». Сервер сам читает сохранённый документ; клиент передаёт только ожидаемые версии черновика и публикации. Одна атомарная операция проверяет обе версии. Черновые изменения не меняют опубликованный документ. `/api/game` и `/play` используют этот снимок; до первой публикации получают понятное сообщение, без подстановки черновика. Контрольная сумма опубликованного проекта проверяется при чтении; повреждённая редакция не допускает загрузки и записи аккаунтного прогресса.

Автор может читать свои прежние файлы для отмены и резервных копий. Другие посетители получают только идентификаторы ресурсов из опубликованного документа. Авторские ответы и ошибки не кэшируются. Прежние байты ресурсов остаются неизменными.

У каждого подтверждённого аккаунта есть автослот и пять ручных слотов. Ключ D1 включает проект, серверный идентификатор пользователя и слот. Идентификатор из JSON или строки запроса не выбирает чужие данные. Заголовок `x-morimundus-account` только сверяет аккаунт, для которого открыта вкладка: полномочия определяет подтверждённая сервером личность. После смены аккаунта в другой вкладке старое чтение, запись и удаление отвечают 409, сохраняя обе группы слотов.

Запись использует ожидаемую версию слота и актуальную опубликованную редакцию. Конкурирующий запрос получает 409; удаление сохраняет номер версии, предотвращая восстановление слота старой вкладкой. Неизменное содержание можно опубликовать повторно: прогресс переносится на новый номер редакции без повторного исполнения событий. При изменённом содержании прежний слот остаётся видимым, но несовместимым. Прежние авторские `game_saves` остаются отдельными проверочными слотами, без неоднозначного переноса в аккаунты игроков.

Гостевые слоты используют версионированные записи localStorage и эксклюзивные Web Locks на слот. Поддержаны целостность, совместимость, конфликт двух вкладок, сохранение предыдущих байтов при переполнении и явный повтор. Чтение не создаёт записей и не отправляет прогресс на сервер. Повреждённый JSON не перезаписывается молча; удаление требует явного действия. Очистка данных сайта удаляет гостевой прогресс. Без Web Locks запись безопасно отклоняется с предложением использовать серверные слоты. Вход открывает отдельные аккаунтные сохранения; автоматического слияния нет.

Миграция `0002_futuristic_bushwacker.sql` добавляет `author_accounts`, `published_games` и `player_saves`. Прежние миграции, снимки и таблицы сохранений не изменены. Первичный составной ключ обслуживает список и чтение слота без дополнительного индекса; проверен EXPLAIN QUERY PLAN. Локальная миграция применена, новые зависимости не добавлены.

| --- | --- | --- |
| Игрок не читает и не меняет авторские данные | Пройдено | Настоящие локальные HTTP → Worker → D1/R2; личности моделируются доверенными заголовками тестового клиента |

| WebGL, звук, FPS и память | Открыто | Сохраняются ограничения приёмки предыдущих этапов |

При диагностике последовательность ранних отказов приводила к ошибке `Can't read from request stream after response has been sent`, после которой следующий запрос иногда получал 503 от прокси Wrangler. После ограниченного завершения небольших отклонённых тел ошибка в диагностическом прогоне не повторилась, полный Worker прошёл. Обработчик отбрасывает данные без разбора, не меняет исходный статус отказа и ограничен 64 КиБ и тремя секундами; для большего или зависшего тела прекращает чтение. Повторные отказные запросы включены в постоянную проверку. Это наблюдение локальной среды, а не доказательство поведения всех сетевых сбоев в продакшене. Связанный механизм описан в [Cloudflare workerd #1730](https://github.com/cloudflare/workerd/issues/1730); собственный результат основан на локальных логах и запросах.

По React-инструкции просмотрены границы компонентов, зависимости эффектов, отмена запросов, подписки и освобождение координаторов. Проигрыватель загружается динамически после команды «Играть», кнопка стоит перед длинным описанием. Проект, редакция, аккаунт и транспорт фиксируются для запуска. Ошибки и ожидание имеют текстовые состояния; публикация использует существующие Button и AlertDialog. Это просмотр исходников, фактический фокус и клавиатура не проверены. Сборка по-прежнему предупреждает о крупном клиентском фрагменте; замеров скорости нет.

## Открытая браузерная приёмка

Разрешённый `control-browser` отсутствует. [Инструкция Sites](sandbox:/root/.codex/plugins/cache/openai-curated-remote/sites/0.1.75/skills/sites-building/SKILL.md), ссылка на `references/preview/managed-linux.md`, предписывает: “If it is unavailable, do not improvise another browser-control path.” Другой путь не использован. Публикация допускается без браузерной проверки; ручная приёмка этапов 2–11 остаётся открытой.

1. Войти автором, сохранить проект и опубликовать первую редакцию. Открыть `/play`, проверить запуск, меню, выход, состояния ожидания и ошибок. Изменить черновик и убедиться, что игра меняется только после следующей публикации.
2. При отдельно разрешённом владельцем расширении аудитории войти двумя настоящими аккаунтами игроков. Проверить отказ мастерской и авторских API, недоступность файла черновика и отдельные списки слотов. Аудитория сайта на этом этапе остаётся только для владельца.
3. На первом физическом устройстве сохранить мир посреди текста или приготовления, перейти на второе устройство с тем же аккаунтом и продолжить. Проверить положение, вещи, таймер, задания, позы и отсутствие повторной награды. Прогресс другого аккаунта должен остаться прежним.
4. Оставить игру открытой, сменить аккаунт в другой вкладке и попробовать чтение, запись и удаление. Получить сообщение об изменившемся аккаунте; ни одна группа слотов не должна перезаписаться. Проверить явное обновление страницы и выбор продолжения.
5. Для гостя проверить обновление и повторное открытие браузера, две вкладки с конфликтующей записью, ошибку заполненного/запрещённого хранилища и явный повтор. После входа увидеть отдельные аккаунтные слоты; после выхода — прежние гостевые. Не очищать реальные данные без намерения удалить прогресс.
6. На двух авторских вкладках проверить конкурентную публикацию и конфликт версии. Сравнить неизменное повторное содержание и новую редакцию. Проверить клавиатуру, Escape и возврат фокуса подтверждения, закрытие страницы во время запроса и повтор после сбоя сети.
7. Продолжить маршруты интерфейса, WebGL, Pointer Lock, слышимого звука, FPS и памяти из отчётов предыдущих этапов.

По автоматическим результатам дополнительная итерация реализации не требуется. Можно переходить к этапу 12 — проверке игрового цикла; реальный вход, физические устройства и нативная браузерная приёмка пока не подтверждены.
