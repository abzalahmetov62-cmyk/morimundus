# Игровые данные Morimundus

Этот снимок переносит содержимое игры вместе с кодом Sites версии 35, коммит `df3e20f8780a920737ebb104235f82037a824c35`.

- `author.json`: авторский проект из резервной копии `Morimundus-2026-10-31.rar`, внутри — `Morimundus-2026-10-31.json`. Содержит 13 сцен, 2 локации и 62 ресурса. Формат оболочки — `{ "project": ... }`.
- `published.json`: отдельно выгруженная опубликованная игра, редакция 8, созданная из авторской редакции 150. Она сохраняется отдельно от более нового черновика.
- `assets.json` и `assets/`: оригинальные изображения и аудио обоих документов, MIME, размеры, SHA-256 и ключи файлового хранилища. Все 62 файла проверены; общий объём — 146 272 764 байта.
- `seed.sql`: восстановление документов и каталога ресурсов в отдельной пустой базе после применения миграций.
- `snapshot.json`: происхождение данных, версия исходников и результаты проверок.

Доступное чтение живой базы Sites ограничивает размер длинных ячеек. Поэтому полный черновик взят из авторской резервной копии, а не из обрезанного ответа базы. Доступное начало документа (1745 символов) и метаданные всех ресурсов совпали с живой базой. В ней на момент проверки наблюдалась редакция 168 от 26 октября 2026 года. Полное побайтовое совпадение документа с редакцией 168 не подтверждено; номер этой редакции не приписывается резервной копии.

## Восстановление в отдельной среде

1. Установить зависимости согласно `package.json` и `pnpm-lock.yaml`. Проверить код: `node node_modules/typescript/bin/tsc --noEmit`, затем `npm run build`.
2. Выполнить `node scripts/check-project-snapshot.mjs --extract-assets`: проверяются схема документов, наличие ресурсов, размеры и SHA-256. Оригинальные файлы для загрузки будут подготовлены в `work/restored-assets/`. Один крупный WAV хранится в GZIP из-за лимита инструмента передачи GitHub; распаковка полностью восстанавливает исходные байты. Повторный запуск сверяет существующие файлы, не перезаписывая отличающиеся данные.
3. Создать отдельную базу Cloudflare D1 и применить `drizzle/*.sql` по порядку. Загрузить подготовленные оригиналы из `work/restored-assets/` в отдельный бакет R2, используя `storageKey` и `mime` из `assets.json`.
4. Выполнить `seed.sql` в пустой базе. Используются обычные INSERT: при существующих строках импорт остановится, не перезаписывая их. Авторский документ получает новую локальную редакцию 1; опубликованный документ сохраняет исходную информацию о публикации.
5. Подключить D1 и R2 к приложению как `DB` и `BUCKET`. Настроить ChatGPT Identity и задать `MORIMUNDUS_AUTHOR_EMAIL` отдельно через окружение. Учётная запись автора будет привязана при первом подтверждённом входе.

JSON и файлы в этой папке не импортируются автоматически при запуске приложения. Идентификатор в `.openai/hosting.json` относится к существующему Sites; для другого размещения нужны отдельные настройки. Оптимизированные копии изображений создаются заново приложением из оригиналов.

Секреты, файлы окружения, привязки аккаунтов, сохранения игроков, зависимости, кэши, результаты сборки и удалённые/неиспользуемые записи ресурсов не входят в снимок. Данные действующего Sites не изменялись, новая версия игры не публиковалась.
